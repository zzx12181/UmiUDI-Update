### 一、 官方规范文档体系
1. **《国家药品监督管理局医疗器械唯一标识数据库对接申请表》**（加盖公章提交审核）；
2. **《医疗器械唯一标识管理信息系统业务申报API标准文档》**：
   - 面向对象：医疗器械注册人/备案人及其受托对接系统（如 MES / ERP）；
   - 核心功能：通过 HTTPS RESTful API 接口，上传并维护产品标识 (DI) 主数据、扩展技术属性及多级包装数据；
   - 报文格式：JSON 格式，UTF-8 编码；
   - 鉴权认证：基于企业申请审核通过后发放的 `AppKey` 与 `AppSecret`，采用 HMAC-SHA256 签名校验。
3. **《医疗器械唯一标识管理信息系统数据共享API标准文档》**：
   - 面向对象：流通企业、各级医疗机构、医保部门及第三方公众平台；
   - 核心功能：提供依据 DI、GTIN、注册证号的批量检索与全量数据下载（含每日增量同步接口）。
4. **《医疗器械唯一标识信息系统数据导入模板》**：
   - 适用场景：未完成系统 API 直连的中小企业通过 Excel/XML 批量导入建档。

---

### 二、 标准对接流程规范
1. **申请准备**：企业登录 CUDID 门户下载《对接申请表》，如实填写系统开发商资质、通信 IP、联系人，加盖公章并上传 PDF 扫描件；
2. **密钥获取**：国家药监局信息中心在 3~5 个工作日内完成合规核验，通过邮件发放测试与生产通信密钥；
3. **测试联调**：在测试沙箱接口验证数据字段格式（遵循 YY/T 1752-2020 基本数据集要求）与签名安全算法；
4. **正式上线**：通过联调验收后切换至正式环境，开展上市前 DI 主数据自动上传。
