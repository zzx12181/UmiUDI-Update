# 医疗器械独立软件 (SaMD)、人工智能与网络安全合规指南

## 一、 医疗器械软件分类与监管界定
根据国家药监局《医疗器械软件注册审查指导原则（2022年修订版）》：

1. **独立软件 (SaMD - Software as a Medical Device)**：
   - 具备医疗器械功能、本身即为医疗器械的软件（如医学影像处理软件、心电辅助分析系统）；
   - 作为独立医疗器械申报注册，通常按二类或三类管理。
2. **软件组件 (SiMD - Software in a Medical Device)**：
   - 作为医疗器械组成部分或控制部件运行的嵌入式固件/上位机软件（如生化分析仪控制软件、呼吸机固件）；
   - 随整机一同申报注册。

---

## 二、 软件生命周期与版本命名规范
1. **生命周期过程（IEC 62304 / YY/T 0664）**：
   - 软件开发策划 -> 需求分析 -> 架构设计 -> 详细设计 -> 单元测试 -> 集成测试 -> 系统验证 -> 软件发布与维护。
2. **软件版本命名规则**：
   - 必须明确“完整版本”与“发布版本”规则；
   - 规范格式示例：`V X.Y.Z.B`（X 为重大架构/算法变更，Y 为功能变更，Z 为缺陷修复，B 为构建号）；
   - **重大软件更新**（涉及算法原理、用户操作模式或适应证变更）需办理注册变更；轻微更新（Bug修复、性能优化）列入质量管理体系记录并在下次变更时报备。

---

## 三、 医疗器械网络安全与数据安全要求
依据《医疗器械网络安全注册审查指导原则》：
1. **核心原则**：机密性（Confidentiality）、完整性（Integrity）、可用性（Availability）；
2. **网络安全能力要求**：
   - 自动用户身份鉴别、基于角色的权限控制（RBAC）；
   - 敏感患者健康信息（PHI）与追溯数据传输加密（TLS 1.2+、AES-256）；
   - 审计追踪（Audit Trail）：详细记录用户登录、配置变更、数据导出与关键业务操作，日志不可篡改；
   - 网络安全漏洞（CVE）应急响应机制与安全补丁分发管理。
